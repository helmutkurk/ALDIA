# UX decisions 2026-11-21

Decided by Fernando with the approval of Isa (portal) and Helmut (app), answering the ★ questions in
[`app/docs/ux/open-decisions.md`](../../app/docs/ux/open-decisions.md). Specs: [`app/docs/ux/`](../../app/docs/ux/).
Nothing here changes code yet; the app and the portal follow these decisions when Phase 3 implements each screen.

## Account

1. **Login method: phone code.** The built flow stays: `+502`, eight digits, six-digit code. Citizen ID (DPI) is a
   possible second method **in the future**: screens and the auth service must leave room for a second method, but it is
   not designed or built now. A real SMS/WhatsApp provider is still pending.
2. **Sign in at send, not at app start.** Citizens can browse, explore and fill in the whole report without an account.
   On **Revisar y enviar**, a citizen without an account gets the phone-code sheet before the report is sent; after
   verification the report is sent. The MVP test account remains until the team removes it.

## Report flow

3. **Nearby reports only when there are matches.** After **Categoría**, the app asks `GET /api/reports/nearby`. If it
   returns at least one report, a step "¿Es este tu reporte?" shows them with **Seguir este reporte** (finish without
   uploading) and **No, es otro problema** (continue). With no matches, or offline, the step is skipped and does not block.
   The step counter counts only the steps shown.

## Wording

4. **Citizen words in public, official words for staff.** The app and the public portal pages (map, list, report page,
   shared links) use the citizen wording of `app/lib/core/citizen_states.dart`. The staff screens (staff mode, triage,
   transitions) keep the official words (`No procede`, `Fuera de competencia`, …).

## Visual design

5. **New palette for the app and the portal together**, as in [`app/docs/ux/design-direction.md`](../../app/docs/ux/design-direction.md).
   `documentation/design-tokens.md` is replaced when the shared tokens are implemented (Phase 3), not before, so it
   keeps describing the code that runs.
6. **Contrast fixes accepted.** Buttons and links use `#2A6FA8` (pressed `#235E8F`). `#4997D0` and `#2F7FBF` stay for brand
   marks, large text and non-text marks. The 4.5:1 text rule and its tests stay.
7. **Accent: coral `#FF7A59`**, as a fill with dark text `#1F2933`; `#B4472B` when coral is used as text.
8. **New status colors:** open amber `#B26A00`, in work violet `#7E57C2`, resolved green `#17735A`, closed gray `#6B7280`,
   rejected red `#B91C1C`, pending outlined `#52606D`. Always with the state word. Portal pins and charts change too.

## Explorar map (after the wireframe review, same day)

11. **Full-screen map.** Explorar shows the map over the whole screen above the bottom bar. Floating controls: back
    (top left), a **Mapa | Lista** switch (top center), a filter button with a count of active filters (top right),
    zoom (left), a legend of state colors (bottom left), my location and layers (bottom right), OpenStreetMap credit.
    Pins show the category icon on the state color; clusters show a count. The list view uses the same header.
12. **Filters in a bottom sheet:** search, category chips and state chips, **Aplicar filtros** and **Quitar filtros**.
    It replaces the chip row and the search in the top bar. There is no priority filter: the API has no priority field.
13. **No floating "+" button on the map.** Reporting stays in the center **Reportar** item of the bottom bar.
14. **Explorar stays under Inicio** (opened with **Explorar mi ciudad**, closed with back); it is not a new tab.
15. **No dark top bar.** Inicio and Explorar use light surfaces, as in the approved wireframes (open-decisions #24).
